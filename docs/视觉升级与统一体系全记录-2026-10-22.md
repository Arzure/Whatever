## 一、历史待办核实（两项，均已闭环）

### 1. PayloadTooLargeError（请求体过大报 413）

**问题**：用户输入很长的文本时，服务器直接报错拒绝。

**原因**：服务器解析 JSON 请求体的默认上限只有 64KB，长文本超限。

**核实结论**：修复早已入库——提交 6c2aeec 把全局上限从 64KB 提到 1MB，另外给两个特殊接口单独放宽：绘图接口 40MB（要传图片）、办公接口 20MB。当前代码分层限制均生效。

### 2. 推理杀思考解析修复的提交状态

**核实结论**：四个相关提交（631910d 大纲过滤思考碎语、c68fb70/1be14ec/945cba4 思考兜底解析系列）均已被远端 main 分支包含，即全部已推送，无遗漏。

**方法**：用 `git branch -r --contains 提交号` 检查某提交是否已在远端分支里——这是核实『代码到底推没推上去』的标准命令。

## 二、视觉阶段二：顶栏毛玻璃（含完整踩坑记录）

### 1. 什么是毛玻璃效果

毛玻璃 = 半透明底色 + `backdrop-filter: blur(模糊半径)`。浏览器会把**这个元素背后**的内容先模糊一遍，再叠上半透明底色，看起来就像磨砂玻璃。

### 2. 第一个坑：毛玻璃完全看不出来

**现象**：代码写了 `backdrop-filter: blur(24px)`，但页面上毫无效果。

**根因**：`backdrop-filter` 只能模糊『元素背后正在经过的东西』。当时顶栏是普通文档流元素（跟着内容一起从上往下排），滚动发生在下方视图内部——**内容永远不会从顶栏底下穿过**，顶栏背后只有页面的纯色背景。模糊一块纯色，当然什么都看不出来。

**修复**：把顶栏改成 `position: fixed`（固定悬浮在屏幕顶部，不随页面滚动），内容从它底下穿过，滚动时文字卡片从毛玻璃后掠过被实时模糊，效果立刻可见。

### 3. 第二个坑：内容被顶栏盖住

顶栏悬浮后，页面最顶部的内容会被它挡住。解决方法：给内容区让出顶栏的高度。

**实现**：用 ResizeObserver（一个浏览器提供的『元素尺寸变化监听器』）把顶栏实际高度写进 CSS 变量 `--bar-h`，各视图的滚动容器用 `padding-top: var(--bar-h, 48px)` 让位。手机上按钮换行导致顶栏变高时，让位高度自动跟着变。

### 4. 第三个坑：让位内边距加错了地方（毛玻璃又看不见了）

一开始把让位内边距加在**内容区**上——结果滚动容器的顶边永远在顶栏下方，内容还是不会从顶栏底下穿过，毛玻璃又失效了。

**正确做法**：让位内边距要加在**各视图自己的滚动容器**上（内边距在滚动区域内部，滚动时内容会穿过内边距区域，即从毛玻璃后掠过）。

### 5. 深浅主题的毛玻璃差异（原理）

- 深色模式效果好：浅色文字卡片从深色顶栏后穿过，明暗对比强烈，模糊非常醒目。
- 浅色模式效果弱：页面内容大多是白底卡片，白色内容透过白色底色被模糊，结果还是白色——『白上加白』天然缺乏对比。这是浅色主题做毛玻璃的普遍难点，不是实现错误。

**最终参数**（经多轮反馈调整定稿）：
- 深色顶栏：底色不透明度 0.55 + blur(24px) saturate(1.6)
- 浅色顶栏：底色不透明度 0.15 + 同样的模糊强度（模糊单独加强的版本试过一轮，按反馈回退）

### 6. 滚动阴影

顶栏加了 `.scrolled` 状态类：监听页面任何滚动容器（用事件捕获阶段监听，能捕捉到各视图内部各自的滚动），滚过 8px 后顶栏底部阴影渐显，强化『内容悬浮在顶栏下方』的层次感。

### 7. 鼠标跟随光晕（加入 → 删除）

曾实现全局鼠标跟随柔光（rAF 缓动跟随、深浅主题双色），用户反馈效果不好，**整体删除**。保留的教训：视觉改动以用户主观感受为最终标准，不合适就干净回退，不留残余代码。

## 四、回归修复：诡异换行（padding 简写陷阱）

**现象**：推理杀侧栏『法官』两个字竖着排成一字一行，『主菜单』按钮断成『主菜/单』两行。

**根因**：CSS 的 padding 简写规则——
- `padding: 10px` → **四个边**都是 10px
- `padding: 10px 20px` → 上下 10px、左右 20px
- `padding: 10px 20px 30px` → 上 10px、左右 20px、下 30px

让位改造时写了 `padding: calc(var(--bar-h) + 16px)`（单值简写），本意只给顶部让位，结果 64px 内边距加到了四边。侧栏宽 280px，左右各吃掉 48px 后内容区只剩约 150px，文字被挤成一字一行。

**修复**：全部改为三值写法，让位高度只加顶部，左右底恢复原值。共修复四个视图八处。

**教训**：改 padding 时永远写清楚几个值，单值简写极易在『只想改一边』的场景误伤四边。

## 六、统一图标体系

### 问题
全站约 101 处 emoji 当图标用（🏠 📂 ☀️…），各平台渲染样式不一、大小不可控、颜色不能跟随主题。

### 方案
新建 `frontend/src/components/Icon.vue`：
- 内联 SVG 线性图标（stroke 1.5px、圆角端点、24x24 网格），内置 26 个图标；
- `stroke="currentColor"`——线条颜色自动继承文字颜色，深浅主题零成本适配；
- 零外部依赖（不装图标库，构建体积几乎不变）。

### 替换范围（31 处界面操作图标）
顶栏全部按钮、首页三张入口卡片、办公页头部与 7 个标签页、绘图工作台标题与 4 个模式切换、冒险/管理页头部、各处关闭与删除按钮。

### 保留不动（约 40 处）
游戏内容性 emoji（消息文本里的 💀、终局谢幕等）——它们是游戏叙事表达，不是界面图标。

## 七、统一按钮体系

### 问题
按钮样式分散在 12 个文件共 83 处定义，各写各的：内边距有两种（10px 18px / 12px 22px）、字号有两种（14/15px）、冒险页主按钮配色还偏离了体系。

### 方案
在全局 `style.css` 建立四层级体系，各视图删除重复定义（净减 132 行）：

| 层级 | 类名 | 视觉 |
|---|---|---|
| 主按钮 | `.btn.primary` | 主题色渐变填充（深色金底深字 / 浅色紫底白字） |
| 危险按钮 | `.btn.danger` | 红色渐变 |
| 幽灵按钮 | `.btn.ghost` | 透明底 + 描边 |
| 通栏按钮 | `.btn.full` | 占满整行（宽度修饰，可与上面组合） |

统一微交互：hover 上浮提亮、active 按压回缩、disabled 半透明；按钮内图标自动对齐（inline-flex + gap）。

**关键知识点——scoped 样式优先级**：Vue 的 `<style scoped>` 生成的选择器带属性限定，优先级高于全局同名选择器。所以只加全局样式不够，**必须删掉各视图的旧定义**，统一体系才能真正生效。

## 八、知识点卡片（速查）

| 知识点 | 一句话解释 |
|---|---|
| backdrop-filter | 模糊元素**背后**的内容；背后没有东西经过就看不到效果 |
| position: fixed | 固定在屏幕上不随滚动移动，是毛玻璃可见的前提 |
| padding 简写 | 单值=四边；只想改一边时务必用三值写法或 padding-top 单属性 |
| z-index | 层叠顺序，弹窗必须高于固定顶栏（70） |
| CSS 变量 | `--bar-h` 这类自定义值，一处定义处处引用，改一处全局生效 |
| ResizeObserver | 监听元素尺寸变化的浏览器 API，用于顶栏换行时同步让位高度 |
| 事件捕获阶段监听 | addEventListener 第三个参数 true，能捕捉到内部各滚动容器各自的滚动 |
| currentColor | SVG 线条自动继承文字颜色，图标深浅主题零成本适配 |
| Vue :key 重播动画 | key 变化 → 元素重建 → CSS 动画自动重新播放 |
| git log -S / branch -r --contains | 分别用于搜『这个改动是哪个提交引入的』和『这个提交推没推』 |
| scoped 样式优先级 | scoped 选择器优先级高于全局，统一体系必须删除旧定义才生效 |
