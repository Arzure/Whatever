# 绘图工作台 · 技术文档（学习版）

> 本文档讲解万象工坊绘图工作台（文生图 / 图片编辑 / 历史管理）的完整技术实现，面向希望理解本项目图像管线并独立开发的工程师。
> 所有内容基于项目实际代码（`server/draw.js`、`server/index.js`、`frontend/src/components/DrawView.vue`）与真实开发过程整理，配套的逐日开发细节见《开发记录》。

---

# 1. 功能概览

绘图工作台是独立于文字冒险的生图玩法，不入存档体系。提供四个核心能力：

- **文生图**：输入提示词生成图片（`POST /api/draw/generate`）
- **图片编辑（图生图）**：上传 1-5 张参考图 + 编辑提示词（`POST /api/draw/edit`）
- **风格模仿**（阶段 3，移植 sn-image-imitate）：上传一张风格参考图 + 描述新图内容 → VLM 先分析参考图的配色/排版/质感，再组装提示词生成同风格新图（`POST /api/office/imitate`，mode 为 `imitate` 入绘图历史）。原技能是三阶段管线（标注→改写→生图→布局审查重试），Web 简化为两步，省略布局蓝图 JSON 与审查重试（模型容量与耗时限制），保留『风格锁定 + 内容替换』核心思想
- **历史管理**：生成记录 24 小时保留，支持查看与删除（`GET /api/draw/history`、`DELETE /api/draw/history/:id`）

前端入口：首页『🎨 绘图工作台』卡片 → `DrawView.vue` 组件（`state.view === 'draw'`）。

# 2. 图像生成管线（server/draw.js）

## 2.1 商汤图像接口对接

图像接口地址独立于 LLM 接口，默认 `https://token.sensenova.cn/v1`（可用 `IMAGE_BASE_URL` 覆盖）：

- 文生图：`POST /v1/images/generations`（仅 prompt）
- 图片编辑：`POST /v1/images/edits`（参考图 + 编辑提示词）

参数严格对齐商汤官方文档：

| 参数 | 说明 |
|---|---|
| `model` | 预设 `sensenova-u1.5-fast`（加速版）/ `sensenova-u1.5-lite`（生成编辑一体，构图光影更佳）|
| `n` | 官方限制仅支持 1 |
| `size` | `auto` 或 2K/4K 档位（2048x2048、2720x1536 等），自定义尺寸需 512-4096、32 的倍数、比例 ≤3:1 |
| `watermark` | 是否带水印（显式传入，官方建议）|
| `prompt_extend` | 提示词扩展（默认开启）|
| `output_format` | png / jpeg / webp（默认 webp——体积约为 PNG 的 1/10，加载从 45 秒级降到秒级）|
| `response_format` | 固定 `b64_json`——前端直接展示，不用 24 小时失效的临时 url |

**鉴权**：`Authorization: Bearer <IMAGE_API_KEY>`，未配置时回退 `LLM_API_KEY`，两者都没有则接口返回 disabled。

**超时**：180 秒（2K/4K 大图生成较慢）。

## 2.2 关键实现细节

- **零依赖**：用 Node 20 内置 fetch，不依赖任何图像 SDK
- **参考图校验**：必须是 Data URL 格式（`data:image/png|jpeg|webp;base64,...`），单张 Base64 不超过 12MB，至多 5 张
- **提示词长度**：截断到 2000 字符

# 3. 历史管理（24 小时过期 + 惰性清理）

## 3.1 存储设计

图片存文件系统（`data/draw/`），仅元数据入 SQLite（`draw_history` 表）：id、user_id、mode、model、size、actual（实际分辨率）、prompt、file、created_at、bytes（文件大小）。

**为什么图片不入库**：SQLite 存大 Blob 会让数据库文件膨胀且查询变慢；文件系统 + 元数据是标准做法。

## 3.2 惰性清理（查询时顺带删除）

`storage.listDrawHistory(userId)` 的实现：

```js
const cutoff = Date.now() - DRAW_TTL_MS; // 24 小时
const expired = db.prepare('SELECT file FROM draw_history WHERE user_id = ? AND created_at < ?').all(userId, cutoff);
db.prepare('DELETE FROM draw_history WHERE user_id = ? AND created_at < ?').run(userId, cutoff);
return { rows: /* 未过期记录 */, expired };
```

没有定时任务，过期记录在用户下次查询历史时被顺带删除，文件由调用方 unlink（文件不存在时静默忽略）。

**学习要点**：惰性清理适合『低频访问 + 可容忍延迟清理』的场景，省去常驻定时器的复杂度。

## 3.3 过期清理提示（expiredCount）

用户登录进入工作台时，过期的图片被静默删除，用户会疑惑『图怎么少了』。解决：

- 服务端：`/api/draw/history` 响应新增 `expiredCount: expired.length`
- 前端：画廊顶部条件渲染『N 张图片已超过 24 小时保留期，自动清理』（灰色小字，无过期不显示）

# 4. 图片访问鉴权（HMAC 签名 URL）——本项目最重要的图像管线设计

## 4.1 问题：img 标签带不了请求头

浏览器 `img` 标签发起的请求**无法携带任何自定义 Header**。本项目 /api 请求有两道门：

1. 访问口令中间件（校验 `X-Access-Token` 头）
2. JWT 登录态（校验 `Authorization: Bearer` 头）

`img` 标签两道都过不了，直接 401。这是『刷新后图片无法显示』问题的真实根因（曾误判为 JWT 问题，第一轮只改 JWT 层无效）。

## 4.2 方案：URL 签名

```js
function signDrawFile(userId, name, createdAt) {
  const exp = (Number(createdAt) || Date.now()) + 25 * 60 * 60 * 1000; // 锚定创建时间 + 25h
  const sig = crypto.createHmac('sha256', String(process.env.JWT_SECRET || 'draw-secret'))
    .update(`${userId}:${name}:${exp}`).digest('hex').slice(0, 32);
  return `/api/draw/file/${name}?uid=${userId}&exp=${exp}&sig=${sig}`;
}
```

- 签名绑定 `userId:name:exp` 三元组，篡改任何参数校验失败
- `/api/draw/file/:name` 路由：校验签名 → 数据库确认文件归属该用户（防跨用户访问）→ sendFile
- 口令中间件豁免 `/draw/file/` 路径（该路由自带签名鉴权，安全性足够）
- 签名有效期 25 小时，略长于图片 24 小时保留期：登录拉取列表后，图片未过期就能一直显示

## 4.3 签名锚定创建时间（浏览器缓存的关键）

最初 `exp = Date.now() + 25h`——每次请求历史列表都生成新 URL，浏览器缓存以 URL 为键，URL 变了缓存必然失效。

修复：`exp` 锚定图片创建时间（`created_at + 25h`），同一张图片在保留期内 URL 恒定不变。

## 4.4 浏览器本地缓存

图片响应增加缓存头：

```js
res.setHeader('Cache-Control', 'private, max-age=86400');
```

效果：刷新页面、重进工作台时，未过期图片直接从浏览器缓存加载，不回源消耗服务器流量；只有缓存中没有（首次查看、清缓存、换设备）才从服务器拉取。

**学习要点**：浏览器强缓存两要素——稳定的 URL + 明确的 Cache-Control，缺一不可。签名 URL 方案与缓存天然冲突（时间戳导致 URL 漂移），解法是把时间锚点从『请求时刻』改为『资源创建时刻』。

**缓存分层实测结论**：同标签页刷新走内存缓存（秒出）；新标签页走磁盘缓存（零流量，只有读取解码时间）；首次加载回源。注意自签证书站点在部分浏览器策略下磁盘缓存可能不持久，绑定域名后彻底解决。

## 4.5 小白解读：签名 URL 到底是怎么回事

### 4.5.1 sig 参数是什么？『拼进 URL』是什么意思？

URL 问号后面是『查询参数』，多个参数用 & 连接。图片 URL 实际长这样：

```
/api/draw/file/dw-1792078928507-a2yt3j.webp?uid=u_ccd20f57&exp=1792165328507&sig=ba3f8e9c2d41...
```

- `dw-...webp`：文件名（路径部分）
- `uid=...`：哪个用户的图
- `exp=...`：过期时间（毫秒时间戳）
- `sig=...`：签名（32 位十六进制字符串）——用密钥对 `uid:文件名:exp` 三元组算 HMAC 得到的『指纹』

『拼进 URL』就是把签名值作为其中一个参数写进去。前端页面用 `<img src="这个URL">` 显示图片，浏览器自动请求这个地址。

### 4.5.2 为什么不能把密钥拼进 URL？

因为 **URL 是完全公开的**——它出现在网页源代码、浏览器地址栏、服务器日志里。把密钥放 URL 等于把家门钥匙挂在门把手上：拿到 URL 就拿到密钥，就能伪造任意用户任意文件的合法 URL。

HMAC 的巧妙之处：**签名里包含密钥的影响，但密钥本身不在签名里**。类比：签名是用『只有服务器有的暗号本』对内容加密变换出的指纹——别人能看到指纹，但反推不出暗号本，也改不出合法的新指纹（改了内容指纹就对不上）。

### 4.5.3 为什么服务端可以重算一遍？

HMAC 是确定性算法 + 密钥在服务端。服务器收到请求后，从 URL 取出 uid、文件名、exp，用自己保存的密钥（.env 的 JWT_SECRET）按同样算法重算签名，与 URL 里的 sig 比对：

```
一致 → 放行 ✅
有人篡改了文件名 → 重算结果变了，与 URL 里的旧 sig 不一致 → 401 拒绝 ❌
```

服务端不需要保存任何组合——只需保存密钥，任何请求来了现场重算。这也是密钥绝不能泄露的原因：谁有密钥谁就能算出合法签名。

### 4.5.4 已知限制：URL 泄露后的重放风险

签名 URL 本质是『不记名提货券』：谁持有谁就能取货。签名防『伪造』（改参数），不防『重放』（原样重复使用）——有效期内请求多少次都合法。

实际风险被多层因素压低：
- URL 只发给登录后的本人（要过口令 + JWT 两道门），文件名含时间戳+随机字符，陌生人无法枚举伪造
- 传输走 HTTPS，中间人窃听不到
- 图片 24 小时删除、签名 25 小时失效——攻击窗口只有一天
- WebP 优化后单张仅 300-400KB，即使被刷损失有限

已加固：`/draw/file/` 路径单 IP 限速每分钟 200 次（每张图片一个独立请求，正常浏览画廊完全无感，仅拦截脚本狂刷；命中浏览器缓存的请求不计数）。

# 5. 安全机制

## 5.1 按用户隔离

- 历史查询、删除均带 `user_id` 条件
- 图片访问双重校验：签名（含 uid）+ 数据库确认归属
- 他人存档/图片统一按不存在处理，不暴露存在性

## 5.2 失败限速（10 分钟时间窗口）

登录限速（按用户名）与访问口令限速（按 IP）机制一致：

- 10 分钟窗口内**连续**失败 5 次 → 锁定 10 分钟
- 每次失败记录 `lastFail` 时间戳，距上次失败超过 10 分钟则重新计数
- 验证成功清零

**踩坑记录**：最初版本失败计数永不过期，正常用户隔几天累计输错 5 次就被锁。限速计数器必须有时间窗口，否则偶发失败会跨天累计误伤。

# 6. 前端实现要点（DrawView.vue）

- 模型/尺寸/格式选项从 `/api/draw/config` 拉取（服务端预设清单，前后端单一来源）
- **生成结果用签名 URL 显示**（生成成功后重新拉取服务端历史）：首次加载从服务器拉取并借此建立浏览器缓存，之后刷新直接命中缓存不再回源——这是『生成后立即缓存』的关键，此前用 Data URL（base64 内嵌）显示时，与历史画廊的签名 URL 是不同的 URL，浏览器缓存按 URL 区分，生成时的显示没有为签名 URL 建立缓存
- 历史画廊用签名 URL 渲染 `img`，自动继承浏览器缓存；**按 mode 过滤只显示 generate/edit 记录**（办公助手生成的 infographic/resume 在办公助手页面查看，两个页面历史完全隔离）
- 缩略图统一固定高度 200px + object-fit: cover 裁切显示——外框按缩略图尺寸设计，多列网格中不随长图拉伸（长图会把同行短图外框撑高造成框内空虚）
- 图片编辑支持上传参考图（前端转 Base64 Data URL，请求体上限放宽到 40MB）
- 过期提示：`expiredCount > 0` 时画廊顶部显示灰色小字提示
- 历史条目显示动态剩余过期时间（如『23小时22分后过期』，每分钟刷新）与文件大小（字节格式化为 KB/MB）
- 下载支持格式选择（PNG/JPEG/WebP 三选一，前端画布实时转换，JPEG 自动铺白底防透明区域变黑）

# 8. 代码走读：一次文生图的完整旅程

本节从用户点击『生成』按钮开始，按代码实际执行顺序带您读一遍完整链路。行号以当前代码为准（`server/index.js` / `server/draw.js` / `server/storage.js` / `frontend/src/components/DrawView.vue` / `frontend/src/api.js`）。

## 8.1 起点：用户输入与前端组装（DrawView.vue）

用户在绘图工作台填写提示词、选择模型/尺寸/格式后点击生成按钮，触发组件内的 `generate()` 函数（约第 115 行起）：

1. **前置校验**：提示词非空、模型已选；编辑模式还要求至少上传一张参考图
2. **组装参数**：把表单状态收进一个对象——

```js
const params = {
  model: m,                    // 生效模型（下拉选择或自定义输入）
  prompt: p,                   // 提示词原文
  size: size.value === '__custom__' ? `${customW.value}x${customH.value}` : size.value,
  outputFormat: outputFormat.value,   // 默认 webp
  watermark: watermark.value,
  promptExtend: promptExtend.value,
};
```

3. **调用 API**：`await api.drawGenerate(params)`（编辑模式走 `api.drawEdit`，多带 `images` 参考图数组）

## 8.2 前端请求层（api.js 第 73 行 request 函数 / 第 115 行 drawGenerate）

`drawGenerate` 只是一行封装：`request('/draw/generate', { method: 'POST', body: JSON.stringify(params) })`。

`request` 函数做三件事：
- 拼接后端地址（开发模式经 Vite 代理转发到 3001，生产模式同源直连）
- 自动附加两个请求头：`X-Access-Token`（访问口令，从 localStorage 读）和 `Authorization: Bearer <JWT>`（登录态）
- 解析响应：非 2xx 时抛出后端返回的 error 字段，2xx 时返回 JSON

## 8.3 服务端第一站：两道中间件（index.js 第 21-22 行 + 第 44 行起）

请求到达 Express 后按注册顺序穿过中间件：

1. **请求体解析**（第 21 行）：`app.use('/api/draw', express.json({ limit: '40mb' }))`——绘图路由单独放宽到 40MB，因为图片编辑要上传参考图 Base64（最多 5 张，每张可达数 MB）；其他 /api 路由仍是 64KB
2. **CORS**（第 28 行起）：设置跨域头（仅开发模式浏览器直连时生效）
3. **访问口令中间件**（第 44 行起）：校验 `X-Access-Token` 头。注意两个放行分支：`/health` 健康检查、`/draw/file/` 图片访问（该路由自带 HMAC 签名鉴权，img 标签带不了自定义头，必须豁免）。失败计数按 IP，10 分钟窗口内连续 5 次失败锁定 10 分钟

## 8.4 路由处理函数（index.js 第 190 行）

```js
app.post('/api/draw/generate', async (req, res) => {
  const result = await draw.generate(req.body || {});
  if (result.error) return res.status(400).json({ error: result.error });
  saveDrawResult(req, result, 'generate');
  res.json(result);
});
```

只做三件事：调封装、存历史、回响应。参数校验全部下沉到 draw.js。

## 8.5 参数校验与组装（draw.js 第 39 行 buildBody）

`buildBody` 是唯一的参数校验点：
- **模型名**：正则 `^[A-Za-z0-9._-]+$` 防注入
- **提示词**：非空、截断到 2000 字符
- **尺寸**：`auto` 或预设档位，或自定义 `宽x高`（512-4096、32 的倍数、比例 ≤3:1——商汤官方规则）
- 组装请求体：`{ model, prompt, n: 1, size, watermark, prompt_extend, output_format, response_format: 'b64_json' }`

`response_format: 'b64_json'` 是关键决策：图片以 Base64 内嵌在 JSON 响应里返回，而不是临时 URL——官方 URL 24 小时失效，Base64 让前端拿到即可用、后端落盘即持久。

## 8.6 调用商汤接口（draw.js 第 78 行 callApi）

- **鉴权**：`Authorization: Bearer <IMAGE_API_KEY>`（缺省回退 LLM_API_KEY，都没有则上层返回 disabled）
- **超时**：AbortController 180 秒（2K/4K 大图生成慢）
- **地址**：`IMAGE_BASE_URL`（默认 `https://token.sensenova.cn/v1`）+ `/images/generations`
- **成功**：从响应的 `data[].b64_json` 提取图片 Base64 数组返回 `{ b64s }`
- **失败**：非 2xx 时返回 `{ error: '请求失败（状态码）：前 200 字符' }`——错误对象一路向上传递，路由层转成 400 响应

## 8.7 落盘与入库（index.js 第 141 行 saveDrawResult）

生成成功后，路由调用 `saveDrawResult(req, result, 'generate')`，这是历史持久化的核心：

1. **解析用户**：`userFromRequest(req)` 从 JWT 还原用户身份（未登录静默跳过，不影响生图主流程）
2. **逐张处理**（对 b64s 数组循环）：
   - 生成唯一 ID：`dw-${Date.now()}-${随机6位}`
   - **落盘**：`fs.writeFileSync(DRAW_DIR/文件名, Buffer)`——图片写进 `data/draw/` 目录，文件名即 ID + 扩展名
   - **解析实际分辨率**：PNG 读文件头偏移 16/20 的宽高；WebP 解析 RIFF 头（VP8/VP8L/VP8X 三种编码各自的偏移规则）——`auto` 尺寸的实际输出不确定，落盘时解析一次存库，前端就不用每次加载图片再测
   - **入库**：`storage.saveDrawHistory(user.id, { id, mode, model, size, actual, prompt, file, bytes })`
3. **提示词记录**：`storage.saveDrawPrompt(user.id, prompt)`——写入 draw_prompts 表（UNIQUE 去重），供前端提示词历史点选复用
4. **失败兜底**：整个函数包在 try/catch 里，保存失败只打日志——**历史保存永远不阻塞生图主流程**

## 8.8 入库细节（storage.js 第 148 行 saveDrawHistory）

```js
db.prepare('INSERT OR REPLACE INTO draw_history (id, user_id, mode, model, size, actual, prompt, file, created_at, bytes) VALUES (?, ?, ?, ?, ?, ?, ?, ?, ?, ?)').run(...)
```

better-sqlite3 的预编译语句：SQL 模板编译一次重复执行，参数化查询天然防注入。`created_at` 存毫秒时间戳，是后续过期判断与签名锚点的依据。

## 8.9 响应回传与前端展示

路由 `res.json(result)` 把 `{ b64s: [...] }` 返回前端。前端拿到后**不再直接渲染 Base64**，而是重新拉取历史（见 8.10），用签名 URL 显示生成结果——首次加载从服务器拉一次并借此建立浏览器缓存，之后刷新直接命中缓存。

## 8.10 历史查询链路（index.js 第 291 行 → storage.js 第 153 行）

用户进入工作台（或生成后刷新）时，前端调 `GET /api/draw/history`：

1. **JWT 鉴权**：`userFromRequest` 还原用户，只查自己的记录
2. **惰性清理**（storage.js listDrawHistory）：`cutoff = now - 24h`，先 SELECT 出 `created_at < cutoff` 的过期记录（返回给调用方删文件用），再 DELETE 过期行——没有定时任务，清理发生在每次查询时
3. **签名 URL 生成**（index.js 第 280 行 signDrawFile）：

```js
const exp = (Number(createdAt) || Date.now()) + 25 * 60 * 60 * 1000; // 锚定创建时间 + 25h
const sig = HMAC_SHA256(JWT_SECRET, `${userId}:${name}:${exp}`).slice(0, 32);
return `/api/draw/file/${name}?uid=${userId}&exp=${exp}&sig=${sig}`;
```

**exp 锚定创建时间而非当前时间**是浏览器缓存的关键：同一张图在保留期内 URL 恒定不变，浏览器才能按 URL 命中缓存。25 小时略长于 24 小时保留期，保证图片未过期时签名始终有效。

4. **响应组装**：`{ rows: [...带签名URL], ttlHours: 24, expiredCount: N }`——expiredCount 让前端显示『N 张图片已超过 24 小时保留期，自动清理』

## 8.11 图片访问链路（index.js 第 303 行）

浏览器 `<img :src="签名URL">` 发起请求（**不带任何自定义头**，所以口令中间件必须豁免 `/draw/file/`）：

1. **签名校验**（第 286 行 verifyDrawFileSig）：exp 未过期 + HMAC 重算比对——篡改 uid/exp/sig 任何一项都失败，返回 401
2. **归属确认**：查库确认 `user_id + file` 匹配——签名正确但文件不属于该用户也拒绝，防跨用户访问
3. **缓存头**：`Cache-Control: private, max-age=86400`——允许浏览器本地缓存 24 小时
4. **sendFile**：Express 从磁盘读文件流式返回

## 8.12 删除链路（index.js 第 316 行）

`DELETE /api/draw/history/:id`：查库确认归属 → 删库行 → unlink 磁盘文件（文件不存在时静默忽略）。前端从画廊数组移除该条目。

## 8.13 全链路时序总览

```
用户点击生成
  → DrawView.generate() 组装参数
  → api.drawGenerate() POST /api/draw/generate（带口令 + JWT 头）
  → [服务端] 40mb 解析 → CORS → 口令中间件校验
  → 路由 → draw.generate() → buildBody 校验 → callApi 调商汤接口
  → 商汤返回 { data: [{ b64_json }] }
  → saveDrawResult：解析用户 → 落盘 data/draw/ → 解析分辨率 → 入库 draw_history → 记录提示词
  → res.json({ b64s }) 回传
  → 前端重新拉取 /api/draw/history
  → [服务端] 惰性清理过期 → signDrawFile 生成签名 URL → 返回 rows + expiredCount
  → 前端用签名 URL 渲染 <img>
  → 浏览器 GET /api/draw/file/...（无自定义头）
  → [服务端] 口令豁免 → 验签 → 归属确认 → Cache-Control → sendFile
  → 图片显示，浏览器缓存建立（24h 内刷新不再回源）
```
