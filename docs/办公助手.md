# 办公助手 · 技术文档（学习版）

> 本文档讲解万象工坊办公助手（信息图 / 简历图生成）的完整技术实现，面向希望理解本项目办公能力并独立扩展的工程师。
> 所有内容基于项目实际代码（`server/office.js`、`server/index.js`、`frontend/src/components/OfficeView.vue`）与真实开发过程整理，配套的逐日开发细节见《开发记录》。

---

# 1. 功能概览

办公助手是阶段 1 + 阶段 2 + 阶段 3 的办公能力区域，提供五个能力：

- **信息图**（含乱码自动检测修正）：填写主题内容 → 选布局（12 种）+ 风格（12 种）+ 尺寸 → 生成 → 视觉模型自动检测文字乱码，有乱码则按精确清单调用图片编辑修正（最多两轮），通过后返回（`POST /api/office/infographic`，响应含 `garbleFixed` 修正计数）。前端生成期间显示阶段化进度（生成中→检查文字→修正乱码），修正后显示『已自动修正 N 处乱码文字』。**方案要点**：检测与修正全部复用现有能力（对话模型多模态 + 图片编辑），零新增依赖；修正指令必须逐处列出乱码原文与正确文字（任务从『创作』变『抄写』，实测 15 处一次修正全部成功）；笼统的『把乱码改对』指令无效（模型只能瞎猜重画，修好大字弄坏小字）
- **简历图**（方案 A 重构）：粘贴简历文本 + 可选风格描述 → 图像模型只生成无文字背景模板，全部文字由 sharp + 中文字体程序化绘制合成（`POST /api/office/resume`，`server/resume.js`）——文字 100% 准确，彻底根治生图模型渲染中文的概率性乱码
- **图表解读**（阶段 2）：上传图表截图 + 可选关注问题 → 多模态模型解读数据趋势/异常点/结论建议（`POST /api/office/chart`）
- **报告网页化**（阶段 3，移植 sn-md-to-html-report）：粘贴 Markdown 报告 + 可选风格倾向 → 对话模型创作自包含单文件 HTML 专题页，iframe 预览 + 新窗口打开 + 下载（`POST /api/office/report`）
- **报告写作**（阶段 3，移植 sn-research-report）：选结构模板（全景叙述/对比选型/实体调查/时序追踪/学术综述）+ 填主题 + 可选补充要求 → 按读者认知任务组织的结构化 Markdown 报告（`POST /api/office/report-write`）

**阶段 3 重要实测教训——模型指令容量**：sensenova-6.8-flash-lite 的指令遵循容量很小，报告网页化首版提示词（1502 字，完整移植原技能设计原则）稳定返回空内容；二分排查实测 626 字指令稳定失败、348 字指令稳定成功。与开发记录中图像模型『28 行英文规则文字乱码』同源（模型容量问题，非提示词写法问题）。最终方案：提示词压缩到一句话级核心要求（保留事实/设计从主题推导/技术契约三点），设计细节交给模型自由发挥。**给后续移植的启示：先测模型容量上限，再决定提示词详略**。

**风格模仿**（阶段 3，移植 sn-image-imitate）在绘图工作台提供（文生图/图片编辑/风格模仿三模式），见《绘图工作台》文档——按用户定位放在绘图工具而非办公助手。

前端入口：首页『📊 办公助手』卡片 → `OfficeView.vue`（`state.view === 'office'`）。

生成结果自动进入绘图历史（mode 为 `infographic` / `resume`），继承 24 小时保留、签名 URL、浏览器缓存等全部机制；办公助手页面内嵌自己的历史画廊（按 mode 过滤，条目化显示，与绘图工作台逻辑一致），无需跳转绘图工作台。

支持模型切换（⚡ 加速版 u1.5-fast / ✨ 质量版 u1.5-lite）、图片灯箱预览、历史下载（PNG/JPEG/WebP 三选一）、提示词历史标签（点选复用，与绘图工作台隔离）。

# 2. 提示词体系来源：商汤开源技能移植

## 2.1 关键认知：开源技能不能直接安装

SenseNova-Skills（github.com/OpenSenseNova/SenseNova-Skills，MIT 协议）遵循 agentskills.io 规范，面向 OpenClaw / hermes-agent 等**本地 Agent 运行时**设计——每个技能是一个文件夹（SKILL.md 操作手册 + 辅助脚本），由本地 AI 助手程序读取并自主执行。

Web 应用没有『读取技能手册并自主执行』的机制，所以技能包无法像装软件一样直接使用。正确方式是**移植**：提取技能里的提示词资产（布局指南、风格指南、固定模板），翻译成自己项目的服务端代码。

## 2.2 移植了什么

| 开源技能 | 移植内容 | 去向 |
|---|---|---|
| sn-infographic | 基础提示词模板（占位符体系：LAYOUT/STYLE/LANGUAGE 等）| `buildInfographicPrompt` 的骨架 |
| sn-infographic | 87 种布局定义（精选 12 种常用：便当格、线性流程、中心辐射、数据看板、左右对比、循环环、层级分层、时间轴、四象限、冰山模型、故事山、单焦点）| `INFOGRAPHIC_LAYOUTS` |
| sn-infographic | 66 种风格定义（精选 12 种常用：扁平化、商务孟菲斯、国潮、数据可视化、纸艺拼贴、霓虹未来、瑞士风格、黑板手写、装饰艺术、蜡笔手绘、极简、等距视角）| `INFOGRAPHIC_STYLES` |
| sn-image-resume | 固定三段式作品集简历布局规则（封面区 30-38% / 简历信息区 34-42% / 目录导航区 20-28%，含各区块内部结构、分隔线、排版层级、内容映射规则）| `buildResumePrompt` |

每个布局/风格条目含中文名（前端展示）+ 英文 guidelines（进提示词，图像模型对英文布局指令理解更稳）。

## 2.3 素材获取方法（踩坑记录）

- 当前环境直接抓取 GitHub 网页超时；服务器直连 HTTPS 克隆报 GnuTLS 错误
- 最终方案：服务器用 SSH 协议稀疏克隆——`git clone --depth 1 --filter=blob:none --sparse` + `git sparse-checkout set skills/sn-infographic skills/sn-image-resume`，只下载两个技能目录，跳过仓库中大量示例图片

**学习要点**：稀疏克隆适合只取大仓库局部目录的场景；服务器 SSH 通道可用而 HTTPS 不通时，改用 `git@github.com:` 协议。

# 3. 服务端实现

## 3.1 office.js（提示词组装，纯函数零依赖）

- `buildInfographicPrompt(content, layoutId, styleId)`：按 sn-infographic 基础模板组装——图片规格（类型/布局/风格/语言）→ 核心原则 → 视觉元素 → 文本要求 → 布局指南 → 风格指南 → 色彩规则（只用描述性颜色名，不用十六进制码）→ 用户内容
- `buildResumePrompt(resumeContent, style)`：平衡版提示词（文字准确 + 版面设计兼得）。**四轮实测迭代记录**：
  - 第 0 轮（移植开源技能 28 行英文布局规则）：文字乱码——超出图像模型指令遵循容量；且默认开启的提示词扩展改写会丢失简历具体内容（生成完全虚构的人物）
  - 第 1 轮（精简为 7 行指令）：文字逐字正确，但版面平庸——只按字面排几行文字，失去设计指导
  - 第 2 轮（加回详细版面指导）：版面丰富（模块化卡片/时间轴/头像/图标），但文字回退——公司名模糊、出现乱码
  - 第 3 轮（最终方案）：紧凑版面指导（一段）+ 逐字渲染约束 + 用户内容 + **内容后追加保真强化指令**（『上图中的全部文字必须与上述内容逐字一致，版面设计可以自由发挥，但每一个字都必须来自上述内容』）——文字逐字正确且版面保持模块化设计
  - **关键发现**：模型对紧邻生成内容的指令遵循度更高——内容后的强化指令让文字保真与版面自由度解耦
  - 验证过的输入格式（每行一个条目）已写入前端输入框占位提示；长句经历建议拆行（长句是文字渲染出错高发区）

## 3.2 路由（index.js）

| 路由 | 说明 |
|---|---|
| `GET /api/office/config` | 布局/风格清单 + 预设模型清单 + 可用尺寸 + 默认模型（前端选项渲染依据）|
| `POST /api/office/infographic` | 内容校验（非空、限 4000 字）→ 组装提示词 → 复用 draw.generate |
| `POST /api/office/resume` | 同上，简历文本 + 可选风格 |

关键设计：

- **复用绘图管线**：`draw.generate({ ...p, prompt, watermark: false })`——办公生成图显式关闭水印
- **历史入库**：`saveDrawResult(req, result, 'infographic' | 'resume')`，mode 标记来源；历史记录保存用户原始内容（截断 2000 字）而非组装后的长提示词

## 3.3 尺寸预设

- 信息图：auto / 2048x2048 / 2720x1536 / 1536x2720 / 1664x2496 / 2496x1664（对齐绘图工作台）
- 简历图：auto / 1536x2720（默认，9:16 纵向长图）/ 1664x2496 / 2048x2048

# 3.5 简历图方案 A：背景生成 + 文字程序化合成（2026-10-19 重构）

## 3.5.1 为什么重构：概率性乱码无法根治

简历图最初与信息图同管线：把简历文本和版面指令一起交给图像模型，让模型直接画出带文字的简历海报。实测发现**生图模型渲染中文小字是概率性缺陷**——同一提示词下时好时坏，乱码集中在小字号文字（如『联系方式』变成『各壮方式』）。先后尝试三轮提示词调优（强制竖版尺寸 / 字号硬约束 / 版面精简删小字元素），均无法根治。结论：**对文字准确性要求极高的图像，不能让生图模型画文字**。

## 3.5.2 方案 A 原理：模型管美感，程序管文字

回答核心问题：**是的，模型只生成无文字的背景**。完整流程分四步：

```
用户输入简历文本（每行一条『字段：值』）
        │
        ▼
┌─ 第 1 步：背景生成（图像模型）────────────────┐
│ 提示词要求：竖版抽象设计背景图，顶部 1/5 视觉   │
│ 重心（大色块/渐变），下方大面积浅色干净区域；   │
│ 严禁出现任何文字、字母、数字、符号             │
│ → 产出：1536×2720 无文字背景（WebP）          │
└──────────────────────────────────────────────┘
        │
        ▼
┌─ 第 2 步：文本解析（纯程序）──────────────────┐
│ 每行按『字段：值』解析 → 结构化数据：          │
│ { name: '范例', title: 'UI/UX 设计师',         │
│   sections: [教育/经历/技能/联系方式…] }      │
└──────────────────────────────────────────────┘
        │
        ▼
┌─ 第 3 步：文字层排版（纯程序，确定性）────────┐
│ SVG 程序化排版：坐标确定性计算、超宽自动换行   │
│ （中文按 1、ASCII 按 0.55 估宽）；             │
│ 顶部超大姓名 + 职位胶囊标签 → 各分类模块       │
│ （强调色竖条 + 标题 + 条目列表）               │
│ → 产出：SVG 文字层                             │
└──────────────────────────────────────────────┘
        │
        ▼
┌─ 第 4 步：图层合成（sharp）───────────────────┐
│ sharp 渲染 SVG 文字层为 PNG →                  │
│ composite 叠加到背景图上 →                     │
│ 输出 1536×2720 WebP（质量 92）                 │
└──────────────────────────────────────────────┘
```

**文字 100% 准确的保证**：文字是 SVG + 中文字体（Noto Sans SC）程序渲染的，不是模型画的——从原理上杜绝乱码，不存在概率问题。背景风格每次由 AI 新生成，保持设计多样性。

## 3.5.3 技术依赖

| 依赖 | 用途 | 说明 |
|------|------|------|
| sharp | SVG 渲染 + 图层合成 | 预编译二进制，npm install 即用 |
| Noto Sans SC | 中文字体 | 开源（OFL 协议），8.3MB，存放于 server/fonts/ 并注册到系统字体 |
| fontconfig | 字体发现 | apt 安装，fc-cache 注册后 sharp 的 SVG 渲染才能找到中文字体 |

## 3.5.4 代码结构（server/resume.js，纯函数零状态）

- `parseResume(text)`：逐行解析『字段：值』
- `structureResume(items)`：提取姓名/职位 + 按字段分组条目
- `wrapText(text, maxUnits)`：按显示宽度自动换行
- `buildResumeSvg(data, palette)`：生成 1536×2720 文字层 SVG（封面区 + 分类模块，坐标确定性计算，画布溢出保护）。模块按类型差异化呈现（参考旧版设计）：联系方式用半透明白色圆角卡片、技能用深色胶囊标签流式排布、经历用强调色时间线（竖线 + 实心节点）、模块标题带强调色竖条与装饰短线——设计感与文字准确性兼得
- `composeResume(bgBuffer, data, palette)`：sharp 合成背景 + 文字层 → WebP
- `buildBackgroundPrompt(style)`：背景生成提示词（严禁文字）

路由（index.js `/api/office/resume`）：背景生成 → 文本解析 → 合成 → 入绘图历史（mode=resume），文字配色固定深色系（背景提示词已约束下方为浅色区域，保证对比度）。

## 3.5.5 验证记录

连续三次真实生成 + 视觉模型逐字转录：全部文字清晰无乱码、与输入逐字一致（姓名/职位/教育/经历/技能/联系方式全部正确），生成耗时约 3.7 秒/次。

# 4. 前端实现（OfficeView.vue）

- 双标签页（信息图/简历图）切换，切换时清空结果与尺寸
- 信息图：布局/风格按钮组（选中高亮 + 描述行）+ 尺寸选择
- 简历图：自由文本风格输入（留空自动匹配专业风格）
- **模型选择器**：⚡ 加速版 / ✨ 质量版，选中后显示介绍文案
- **生成结果用签名 URL 显示**（从刷新后的历史取）：首次加载从服务器拉取并借此建立浏览器缓存，之后刷新直接命中缓存不再回源
- **内嵌历史画廊（条目化，与绘图工作台一致）**：调 `/api/draw/history` 后按 `mode in ('infographic','resume')` 过滤只显示办公图；每条显示原始内容（提示词）、类型 · 模型 · 尺寸 · 实际分辨率 · **动态剩余过期时间**（如『23小时22分后过期』，每分钟刷新）；操作按钮：⬇ 下载、🗑 删除；生成成功后自动刷新
- **灯箱预览**：点击缩略图或生成结果弹出全屏预览（黑色遮罩 + 自适应缩放），点任意处关闭
- **图表解读标签页**：文件上传（png/jpeg/webp、8MB 内、即时预览）+ 可选关注问题 + 解读结果展示（固定四段框架：图表类型/数据趋势/异常点/结论建议）
- **简历示例预填**：切到简历标签页时输入框为空则自动填入最佳实践示例（可直接生成体验，也可改成自己的内容）；占位提示保留格式指引
- **踩坑记录**：组件新增生命周期调用（如 onUnmounted 清理定时器）时，必须同步更新顶部 import 语句——遗漏会导致组件渲染崩溃、整个页面白屏（实际发生过并修复）

# 5. 与绘图工作台的关系

办公助手不重复造轮子：图像生成、落盘入库、签名 URL、浏览器缓存、24 小时过期、删除接口全部复用绘图工作台的机制。两者的关系是『同一套图像管线上的两种业务入口』——绘图工作台面向自由创作（用户自己写提示词），办公助手面向场景化生成（服务端替用户组装专业提示词）。

扩展新办公能力（如阶段 2 的 Excel 分析、图表解读）时，按同样模式：新增提示词组装函数 + 路由 + 前端标签页即可。
