# 第 0 章 环境准备与项目结构

## 0.1 你要操作的项目长什么样

```
Whatever/
├── frontend/                  ← 前端（本书全部操作都在这里）
│   ├── src/
│   │   ├── App.vue             ← 应用外壳：顶栏、页面切换都在这
│   │   ├── style.css           ← 全局样式：主题变量、全局按钮体系
│   │   ├── api.js              ← 前端请求后端的接口封装
│   │   └── components/         ← 每个页面是一个 .vue 文件
│   │       ├── HomeView.vue        首页
│   │       ├── DeductionView.vue   推理杀（最复杂的游戏页）
│   │       ├── DetectiveView.vue   侦探模式
│   │       ├── WolfView.vue        狼人杀
│   │       ├── WorldView.vue       大世界
│   │       ├── DrawView.vue       绘图工作台
│   │       ├── OfficeView.vue     办公助手
│   │       ├── AdventureView.vue  文字冒险
│   │       ├── AdminView.vue      用户管理
│   │       └── …
│   └── dist/                  ← 构建产物（npm run build:frontend 生成）
├── server/                     ← 后端（本书不涉及）
└── docs/                       ← 文档（本书就在这里）
```

**一个 .vue 文件 = 一个页面组件**，固定三段结构：

```vue
<script setup>  // ① 逻辑：数据、函数
</script>

<template>     // ② 结构：HTML 模板
</template>

<style scoped>  // ③ 样式：只作用于本组件的 CSS
</style>
```

## 0.2 常用命令

```bash
cd /home/ubuntu/Whatever          # 进入项目根目录
npm run build:frontend            # 构建前端（改完代码必须执行）
pm2 restart ai-rpg --update-env  # 重启服务使构建产物生效
curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:3001/  # 验证首页（期望 200）
```

**开发循环**：改代码 → 构建 → 重启 → 浏览器强刷（Ctrl+Shift+R）→ 肉眼确认。

## 0.3 主题系统现状（先了解，后面要用）

全局样式 `frontend/src/style.css` 里定义了两套颜色变量：

```css
:root {              /* 深色主题（默认） */
  --bg: #131c3a;
  --panel: #1e2a52;
  --panel-2: #263566;
  --border: #4a5c96;
  --accent: #d4a12c;   /* 主题强调色：金色 */
  --accent-2: #8a7bf0;
}
html.light {          /* 浅色主题：同一批变量换值 */
  --bg: #f6f8fc;
  --panel: #ffffff;
  --panel-2: #eef1f8;
  --border: #d8deeb;
  --accent: #6d5ae0;  /* 浅色强调色：紫色 */
}
```

**CSS 变量**（`--名字`）是一处定义、处处引用的值。页面元素写 `background: var(--panel)`，深色模式下就是深蓝，切到浅色模式自动变白——这就是主题切换的全部原理。**写新样式时永远引用变量，不要硬编码颜色**，否则主题切换时你的样式不会跟着变。

# 第 1 章 任务一：顶栏固定悬浮与毛玻璃效果

## 1.1 目标

顶栏（页面最上方那条按钮栏）原本跟着内容一起排布。要改成：**固定悬浮在屏幕顶部，半透明 + 毛玻璃模糊**，页面滚动时内容从顶栏底下穿过、被模糊，像透过磨砂玻璃看东西。

## 1.2 原理（为什么这么做）

毛玻璃的核心是一行 CSS：

```css
backdrop-filter: blur(24px);
```

它模糊的是**这个元素背后**的内容。关键推论：**如果背后永远只有一块纯色背景，模糊纯色 = 什么效果都没有**。所以毛玻璃可见有两个前提：

1. 顶栏必须**悬浮**（`position: fixed`，固定在屏幕上不随滚动移动）；
2. **内容必须从顶栏底下穿过**（滚动时文字卡片从顶栏后方掠过）。

当天踩的三个坑全部源于这两个前提没满足，详见第 4 章。这里直接给出正确做法。

## 1.3 操作步骤

### 步骤 1：改 App.vue 的模板

打开 `frontend/src/App.vue`，找到 `<header class="app-bar">`，给它加一个 ref（让脚本可以引用这个元素）：

```html
<header ref="barEl" class="app-bar" :class="{ scrolled: barScrolled }">
```

### 步骤 2：改 App.vue 的脚本

在 `<script setup>` 里（`const authUser = ...` 附近）加入：

```js
// 顶栏高度同步：顶栏固定悬浮后，用 CSS 变量给各视图滚动容器让位
const barEl = ref(null);
// 顶栏滚动阴影：任一滚动容器下移后顶栏底部阴影渐显
const barScrolled = ref(false);
function onAnyScroll(e) {
  const t = e.target;
  const top = (t === document || t === window || t === document.body)
    ? (window.scrollY || 0)
    : (t.scrollTop || 0);
  barScrolled.value = top > 8;
}

// 顶栏登录后才渲染，侦听它出现后建立高度同步（换行时 ResizeObserver 自适应）
watch(barEl, (el) => {
  if (!el) return;
  const syncBarH = () =>
    document.documentElement.style.setProperty('--bar-h', el.offsetHeight + 'px');
  syncBarH();
  new ResizeObserver(syncBarH).observe(el);
});
```

同时把文件第一行的 import 改为（加 watch）：

```js
import { onMounted, provide, ref, computed, watch } from 'vue';
```

在 `onMounted(async () => { ... })` 里加一行全局滚动监听：

```js
document.addEventListener('scroll', onAnyScroll, true); // true = 捕获阶段
```

**代码解释**：
- `ref(null)`：Vue 的『响应式引用』，模板上的 `ref="barEl"` 会把顶栏元素存进这个变量；
- `watch(barEl, ...)`：顶栏在登录成功后才渲染，挂载时还不存在。watch 会在它出现时自动执行；
- `ResizeObserver`：浏览器提供的『元素尺寸变化监听器』。手机窄屏上顶栏按钮换行、高度变化时，让位高度自动跟着变；
- `setProperty('--bar-h', ...)`：把顶栏实际高度写进 CSS 变量，供各视图引用；
- 滚动监听第三个参数 `true`（捕获阶段）：页面滚动发生在各视图**内部**的容器里，默认监听收不到；捕获阶段的事件会从外向内传播、路过 document，所以挂在 document 上也能捕捉到任何内部容器的滚动。

### 步骤 3：改 App.vue 的样式

找到 `.app-bar { ... }`，改为（关键行已注释）：

```css
.app-bar {
  position: fixed;        /* 固定悬浮在屏幕顶部，不随页面滚动 */
  top: 0;
  left: 0;
  right: 0;
  z-index: 70;           /* 层级：高于内容、低于弹窗（90+） */
  display: flex;
  flex-wrap: wrap;
  align-items: center;
  justify-content: flex-end;
  gap: 12px;
  padding: 8px 16px;
  /* 毛玻璃：半透明底 + 背后内容模糊 + 饱和度提升 */
  background: rgba(19, 26, 46, 0.55);
  backdrop-filter: blur(24px) saturate(1.6);
  -webkit-backdrop-filter: blur(24px) saturate(1.6); /* Safari 兼容 */
  border-bottom: 1px solid rgba(212, 161, 44, 0.22);
  box-shadow: 0 1px 0 rgba(212, 161, 44, 0.1), 0 6px 28px rgba(0, 0, 0, 0.35);
  transition: box-shadow 0.3s ease;
}
```

浅色主题的顶栏（同文件后面找 `html.light .app-bar`）：

```css
html.light .app-bar {
  /* 浅色毛玻璃难点：白底卡片透过白色顶栏，模糊了也看不出来（白上加白）。
     对策：底色调到很透（0.15），让内容尽量透过来被模糊。 */
  background: rgba(255, 255, 255, 0.15);
  border-bottom: 1px solid rgba(109, 90, 224, 0.28);
  box-shadow: 0 1px 0 rgba(109, 90, 224, 0.08), 0 6px 28px rgba(30, 38, 56, 0.1);
}
```

### 步骤 4：给各视图的滚动容器让位（关键步骤，坑最多）

顶栏悬浮后，页面最顶部的内容会被它挡住，必须让位。**让位内边距必须加在各视图自己的滚动容器上**（原因见第 4 章坑三）。

对以下每个文件，找到对应选择器，把 padding 改为『顶部 = 原值 + var(--bar-h, 48px)』的三值写法：

| 文件 | 选择器 | 改前 | 改后 |
|---|---|---|---|
| HomeView.vue | `.home` | `height: 100%;` | `height: 100%; padding-top: var(--bar-h, 48px);` |
| DrawView.vue | `.draw` | `height: 100%;` | `height: 100%; padding-top: var(--bar-h, 48px);` |
| OfficeView.vue | `.office` | `padding: 20px 16px 60px;` | `padding: calc(var(--bar-h, 48px) + 20px) 16px 60px;` |
| AdventureView.vue | `.adventure` | `padding: 20px 16px 60px;` | `padding: calc(var(--bar-h, 48px) + 20px) 16px 60px;` |
| AdminView.vue | `.admin` | `padding: 20px 16px 60px;` | `padding: calc(var(--bar-h, 48px) + 20px) 16px 60px;` |
| DetectiveView.vue | `.side-panel` | `padding: 20px 18px;` | `padding: calc(var(--bar-h, 48px) + 20px) 18px 20px;` |
| DetectiveView.vue | `.messages` | `padding: 24px 28px;` | `padding: calc(var(--bar-h, 48px) + 24px) 28px 24px;` |
| WorldView.vue | `.side-panel` | `padding: 20px 18px;` | `padding: calc(var(--bar-h, 48px) + 20px) 18px 20px;` |
| WorldView.vue | `.messages` | `padding: 24px 28px;` | `padding: calc(var(--bar-h, 48px) + 24px) 28px 24px;` |
| WolfView.vue | `.side-panel` | `padding: 16px;` | `padding: calc(var(--bar-h, 48px) + 16px) 16px 16px;` |
| WolfView.vue | `.messages` | `padding: 20px;` | `padding: calc(var(--bar-h, 48px) + 20px) 20px 20px;` |
| DeductionView.vue | `.side-panel` | `padding: 16px;` | `padding: calc(var(--bar-h, 48px) + 16px) 16px 16px;` |
| DeductionView.vue | `.messages` | `padding: 20px;` | `padding: calc(var(--bar-h, 48px) + 20px) 20px 20px;` |

**注意三值写法**：`padding: 上 左右 下`。让位高度只加在**上**，左右和下保持原值。绝对不要写成单值 `padding: calc(...)`——那会把让位高度加到四边（见第 4 章坑二）。

**为什么加在滚动容器上**：内边距属于滚动区域的一部分，滚动时内容会穿过内边距区域，也就是穿过顶栏后方——毛玻璃才有东西可模糊。加在外层容器上，滚动容器整体下移，顶栏背后又没内容了。

## 1.4 验证

```bash
npm run build:frontend && pm2 restart ai-rpg --update-env
```

浏览器强刷（Ctrl+Shift+R），进入任一页面上下滚动，检查：
1. 顶栏固定在屏幕顶部不动；
2. 文字卡片从顶栏后方穿过时被模糊（深色主题非常明显）；
3. 页面最顶部的内容不被顶栏挡住；
4. 切到浅色主题重复检查（浅色效果天然弱于深色，属正常）。

# 第 2 章 任务二：滚动阴影渐变

## 2.1 目标

页面滚动后，顶栏底部阴影渐显，强化『内容悬浮在顶栏下方』的层次感。

## 2.2 操作

第 1 章步骤 2 已经埋好了 `barScrolled` 状态和滚动监听，模板上也绑了 `:class="{ scrolled: barScrolled }"`。现在只需在 App.vue 样式里加两个状态：

```css
/* 滚动后顶栏：底部阴影渐变加深 */
.app-bar.scrolled {
  box-shadow: 0 1px 0 rgba(212, 161, 44, 0.12),
              0 2px 10px rgba(0, 0, 0, 0.3),
              0 12px 36px rgba(0, 0, 0, 0.48);
}
html.light .app-bar.scrolled {
  box-shadow: 0 1px 0 rgba(109, 90, 224, 0.1),
              0 2px 8px rgba(30, 38, 56, 0.1),
              0 12px 32px rgba(30, 38, 56, 0.18);
}
```

`.app-bar` 本体已有 `transition: box-shadow 0.3s ease`，所以阴影是渐变而非跳变。

## 2.3 验证

构建重启后，滚动页面超过约 8px：顶栏底部阴影应淡入；滚回顶部：阴影淡出。

# 第 3 章 任务三：游戏内三项动效

## 3.1 目标

给四个游戏视图（侦探/狼人杀/世界/推理杀）加：① 消息入场动画；② 按钮微交互；③ 阶段标题动画。

## 3.2 操作

### ① 消息入场动画 + 按钮微交互（四个文件同样操作）

对 DetectiveView.vue、WolfView.vue、WorldView.vue、DeductionView.vue，在 `</style>` 前追加：

```css
/* —— 游戏内动效：消息入场 + 按钮微交互 + 阶段标题动画 —— */
.msg { animation: msg-in 0.32s ease both; }
@keyframes msg-in {
  from { opacity: 0; transform: translateY(10px); }
  to   { opacity: 1; transform: none; }
}
.btn { transition: transform 0.12s ease, filter 0.15s ease; }
.btn:hover:not(:disabled) { transform: translateY(-1px); filter: brightness(1.15); }
.btn:active:not(:disabled) { transform: scale(0.96); }
.phase-badge { animation: badge-in 0.55s ease both; }
@keyframes badge-in {
  from { opacity: 0; letter-spacing: 0.45em; }
  to   { opacity: 1; letter-spacing: normal; }
}
```

**代码解释**：
- `@keyframes` 定义动画两个关键帧：从『透明 + 下移 10px』到『完全显示』；`0.32s ease both` 表示时长 0.32 秒、先快后慢缓动、动画前后都应用关键帧样式（防闪跳）；
- 消息元素带 `.msg` 类（四个视图的消息列表条目都有），新消息一渲染就播放入场动画；
- 按钮微交互：悬停上浮 1px + 提亮 15%（提示可点），按下缩到 96%（模拟物理按压）；`:not(:disabled)` 保证禁用按钮无反馈。

### ② 阶段标题动画重播（关键技巧）

CSS 动画只在元素**首次渲染**时播放一次。阶段徽章（如『第 N 夜』）是同一个元素，只改文字不会重播动画。解决：给四个视图模板里的阶段徽章加 `:key`：

```html
<!-- 改前 -->
<div class="phase-badge" :class="phase">{{ PHASE_TEXT[phase] || phase }}</div>
<!-- 改后 -->
<div class="phase-badge" :class="phase" :key="phase">{{ PHASE_TEXT[phase] || phase }}</div>
```

**原理**：`:key` 是 Vue 的元素身份标识。key 变化时，Vue 认为这是新元素，销毁旧的、创建新的——新元素首次渲染，动画自动重播。

## 3.3 验证

构建重启后进入推理杀：新发言淡入上浮；悬停按钮上浮提亮、按下回缩；阶段切换（白天→夜晚）时徽章字距收拢淡入。

# 第 4 章 排雷：你会踩到的坑（先读再动手）

当天实际踩过的坑，按时间顺序。**每个坑都先给现象，你遇到时按现象对号入座。**

## 坑一：毛玻璃完全看不见

**现象**：`backdrop-filter` 代码正确，页面上毫无效果。
**根因**：顶栏是普通文档流元素，滚动发生在下方视图内部——内容永远不会从顶栏底下穿过，顶栏背后只有纯色背景，模糊纯色毫无变化。
**解法**：顶栏 `position: fixed` 悬浮（第 1 章步骤 3）。

## 坑二：诡异换行（一字一行）

**现象**：推理杀侧栏『法官』两字竖排成一字一行，『主菜单』断成『主菜/单』。
**根因**：让位内边距写成了单值简写 `padding: calc(var(--bar-h) + 16px)`——单值作用于**四边**。侧栏宽 280px，左右各吃 64px，内容区只剩 152px，文字被挤成一字一行。
**解法**：三值写法 `padding: 上 左右 下`，让位只加上边（第 1 章步骤 4 的表格）。
**教训**：只想改一边的 padding，永远不要用单值简写。

## 坑三：让位加错地方，毛玻璃又看不见了

**现象**：顶栏悬浮了、让位也加了，毛玻璃还是没效果。
**根因**：让位内边距加在了外层内容区（.app-body）上——滚动容器整体下移到顶栏下方，顶栏背后又没内容了。
**解法**：让位加在**各视图自己的滚动容器**上（第 1 章步骤 4）。

## 坑四：浅色主题毛玻璃几乎不可见

**现象**：深色效果很好，浅色看不出来。
**根因**：浅色页面内容大多是白底卡片，白色内容透过白色顶栏被模糊，结果还是白色——白上加白，天然缺乏对比。**这是浅色主题做毛玻璃的普遍难点，不是实现错误。**
**解法**：浅色顶栏底色不透明度调低（最终定稿 0.15），让内容尽量透过来。曾试过给浅色单独加强模糊（blur 30px），效果不自然，按反馈回退——**视觉参数的最终标准是用户主观感受**。

## 坑五：scoped 样式优先级（第 6 章会用到）

**现象**：全局定义了统一按钮样式，页面上没生效。
**根因**：Vue 的 `<style scoped>` 会给选择器加属性限定（如 `.btn[data-v-xxx]`），优先级**高于**全局同名选择器，旧定义会覆盖新全局样式。
**解法**：统一体系必须**删除**各组件里的旧定义，不能只加全局样式。

# 第 5 章 任务四：统一图标体系

## 5.1 目标

全站约 101 处 emoji 当图标用（🏠 📂 ☀️…）。emoji 的问题：各平台渲染长得不一样、彩色图片无法跟随主题变色、大小无法精确对齐。目标：界面操作图标全部换成统一的 SVG 线性图标；游戏内容里的 emoji（消息文本里的 💀 等）保留——它们是叙事表达，不是界面图标。

# 第 9 章 任务八：PWA 改造（可安装+离线缓存）

## 9.1 目标

手机浏览器访问时提示『添加到主屏幕』，安装后像原生应用一样独立窗口运行；断网后仍能打开页面。

## 9.2 PWA 三件套原理

| 组件 | 作用 |
|---|---|
| manifest.webmanifest | 应用清单：名称/图标/主题色/显示模式，浏览器据此识别『这是个可安装应用』 |
| Service Worker（sw.js） | 后台脚本：拦截网络请求，离线时用缓存响应 |
| 图标 | 主屏幕上的应用图标 |

## 9.3 操作

### ① 生成图标（frontend/public/ 目录，vite 构建时自动拷贝进产物）

用服务器上的 Python PIL + Noto 中文字体生成深蓝底金色『万』字图标：icon-192.png、icon-512.png、apple-touch-icon.png（180，iOS 用）。

### ② 创建 frontend/public/manifest.webmanifest

```json
{
  "name": "万象工坊",
  "short_name": "万象工坊",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#131c3a",
  "theme_color": "#131c3a",
  "icons": [
    { "src": "/icon-192.png", "sizes": "192x192", "type": "image/png" },
    { "src": "/icon-512.png", "sizes": "512x512", "type": "image/png" }
  ]
}
```

`display: standalone` = 独立窗口运行，无浏览器地址栏。

### ③ 创建 frontend/public/sw.js

```js
const CACHE = 'wanxiang-v1';
const SHELL = ['/', '/manifest.webmanifest', '/icon-192.png', '/icon-512.png'];

self.addEventListener('install', (e) => {
  e.waitUntil(caches.open(CACHE).then((c) => c.addAll(SHELL)).then(() => self.skipWaiting()));
});

self.addEventListener('activate', (e) => {
  e.waitUntil(
    caches.keys().then((keys) => Promise.all(keys.filter((k) => k !== CACHE).map((k) => caches.delete(k)))).then(() => self.clients.claim())
  );
});

self.addEventListener('fetch', (e) => {
  const url = new URL(e.request.url);
  if (e.request.method !== 'GET' || url.pathname.startsWith('/api/')) return; // API 不缓存
  e.respondWith(
    fetch(e.request)
      .then((res) => {
        const copy = res.clone();
        caches.open(CACHE).then((c) => c.put(e.request, copy));
        return res;
      })
      .catch(() => caches.match(e.request).then((hit) => hit || caches.match('/')))
  );
});
```

**策略要点**：**网络优先 + 失败回退缓存**——在线时始终拿最新资源（不会出现旧缓存问题），离线时用缓存打开页面；**API 请求一律不缓存**——游戏数据必须实时，离线时操作正常报错而非返回过期数据；缓存名带版本号（v1），更新时 activate 里自动清理旧缓存。

### ④ index.html 注册

```html
<link rel="manifest" href="/manifest.webmanifest" />
<link rel="apple-touch-icon" href="/apple-touch-icon.png" />
<meta name="theme-color" content="#131c3a" />
<script>
  if ('serviceWorker' in navigator && location.protocol === 'https:') {
    window.addEventListener('load', () => navigator.serviceWorker.register('/sw.js').catch(() => {}));
  }
</script>
```

**注意**：Service Worker 只在 https（或 localhost）下可用，注册包了协议判断，http 访问静默跳过不影响使用。

`git log -S`（pickaxe）搜字符串的增删历史；`--contains` 检查提交是否已在某分支。当天用它们核实了两项历史待办（body-parser 限制来自 6c2aeec；思考解析系列提交均已推送）和浅色主题状态（早已在 44fe90e 入库）。**原则：判断做没做过，查仓库，不查记忆。**

## 11.2 回归处理流程

改 A 坏 B（毛玻璃改造引入诡异换行）时的标准流程：
1. **定位**：从症状反推（一字一行 → 空间不足 → 查宽度相关属性 → padding）；
2. **修复**：只改错误部分，不顺手重构无关代码；
3. **全量排查**：`grep -rn 'padding: calc'` 检查所有同类写法，四个视图八处一次修完——**修一处必须排查所有同类**，否则同样的 bug 会分批冒出来；
4. **提交信息写清根因**，方便未来考古。

## 11.3 视觉验收标准

> 视觉类改动的验收标准是**肉眼可感知**，不是『色值变了』——深色底上微调色相等于没改。

- 用户说『看不出变化』时，第一反应应是**怀疑实现路径错了**（如毛玻璃背后没内容），而不是加大参数；
- 参数调整保留快速微调能力；用户反馈『过了』就干净回退（当天光晕整体删除、浅色模糊加强回退，都是这个原则）。
